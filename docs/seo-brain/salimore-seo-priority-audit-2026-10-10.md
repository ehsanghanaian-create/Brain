# ممیزی اولویت SEO Brain سالیمور — ۱۸ مهر ۱۴۰۵

## دادهٔ زنده و حدود آن

در `seo.salimore.com` تنها سایت `salimore` ثبت است. آخرین اجرای موفق WordPress، GSC، GA4، تحلیل و گراف در ۹ اکتبر بوده است. آینهٔ GSC تا ۶ اکتبر (۳۸۰۷ ردیف، ۹۱ روز) و GA4 تا ۸ اکتبر (۱۷۱۱ ردیف، ۶۱ روز) داده دارد. این تاریخ‌ها تأخیر منبع را نشان می‌دهند و نباید «لحظه‌ای» نامیده شوند.

خزش ۹ اکتبر با سقف **۲۰ URL** از ۳۳۵ URL سایت‌مپ به `completed_capped` رسید. جدول `pages` پیش از اصلاح فقط ۱۵۸ URL داشت، درحالی‌که WordPress برای سالیمور ۳۲۲ محتوای ثبت‌شده داشت. سایت‌مپ عمومی هنگام بازخوانی ۱۰ اکتبر ۳۳۹ URL صفحه داشت؛ تغییر ۳۳۵ به ۳۳۹، تغییر خود سایت است و نشانهٔ خطای شمارش نیست. شمار ۱۵۸، پوشش کامل سایت نیست.

تحلیل زنده ۳۷۲ مشکل نشان می‌داد: ۱۵۷ `redirect_in_sitemap`، ۱۳۵ تصویر بدون alt، ۶۲ لینک ورودی کم و ۱۸ مورد دیگر. نمونهٔ URLهای علامت‌خورده با اسلش پایانی در سرور ۳۰۸ می‌دادند، ولی همان URLهای **بدون اسلش** در سایت‌مپ فعلی و با پاسخ ۲۰۰ بودند. کد backend زنده `sitemap_sources` نداشت و URL واقعی سایت‌مپ را پیش از fetch به فرم اسلش‌دار تبدیل می‌کرد. کد توسعه این تفکیک را دارد؛ پس ۱۵۷ مورد را نباید پیش از خزش تازه، مشکل واقعی سایت‌مپ اعلام کرد. دو URL قدیمی که به مقالهٔ جدید redirect می‌شوند، از سایت‌مپ فعلی حذف شده‌اند اما در snapshot قدیمی باقی مانده بودند.

## اصلاح محصول در PR #5

- خزش زمان‌بندی‌شده با بودجهٔ محدود، URLهای هرگزخزیده و سپس قدیمی‌ترین URLها را انتخاب می‌کند. بنابراین ۲۰ URL ثابت هر روز تکرار نمی‌شوند.
- snapshot سایت‌مپ تمام URLهای فعلی را حتی قبل از خزش در `pages` نگه می‌دارد، و URL حذف‌شده را از عضویت سایت‌مپ خارج می‌کند. شکست دریافت سایت‌مپ باعث پاک‌سازی عضویت قبلی نمی‌شود.
- تحلیل اجرای محدود، صفحات تازهٔ ۳۰ روز اخیر را تجمیع می‌کند؛ فقط ۲۰ صفحهٔ آخر را نمایندهٔ کل سایت نمی‌گیرد.
- پاسخ گزارش، سقف خزش، تعداد URL سایت‌مپ، شمار بررسی‌شدهٔ اخیر و وضعیت پوشش را برمی‌گرداند. UI وقتی پوشش ناقص است، امتیاز را «اولیه» می‌نامد و هشدار واضح نشان می‌دهد.

## آزمون عملی روی نسخهٔ جداگانهٔ Salimore

نامزد backend از commit `014f414` ساخته شد. دیتابیس آزمون، کپی خصوصی بکاپ **خود Salimore** بود؛ schema آن تا migration شمارهٔ ۳۹ ارتقا یافت و `PRAGMA quick_check` نتیجهٔ `ok` داد. زمان‌بند و سرویس‌های ورودی فعال نبودند؛ دیتابیس زنده دست‌نخورده ماند.

دو خزش آزمایشی پیاپی با سقف ۵ URL و تنظیمات محافظه‌کارانهٔ یک درخواست هم‌زمان و تأخیر ۲ ثانیه انجام شد. هر اجرا ۵ صفحهٔ موفق و بدون خطا داشت؛ دو مجموعهٔ URL تکراری نبودند. سایت‌مپ هر بار ۳۳۹ URL داشت و پس از ثبت inventory، ۳۳۹ صفحه با نشان `in_sitemap` در کپی ثبت شد. این، موجود بودن صفحه در فهرست را نشان می‌دهد، نه اینکه همهٔ صفحه‌ها بررسی شده باشند.

اجرای تحلیل و گراف روی همان کپی موفق شد: ۱۱۲ مشکل و ۵۷ فرصت ثبت شد. `redirect_in_sitemap` در خروجی تحلیل از ۱۵۷ مورد زندهٔ قدیمی به ۳۹ مورد رسید. این کاهش، ترکیبی از محدودشدن تحلیل به صفحات بررسی‌شدهٔ اخیر، حذف عضویت URLهای خارج‌شده از سایت‌مپ و اصلاح fetch URL اصلی است؛ **اثبات رفع ۱۱۸ مشکل واقعی سایت نیست**. در ستون تاریخی `redirect_chain` هنوز ۱۵۷ ردیف باقی است و نمونه‌های ۳۹ هشدار باقی‌مانده عمدتاً URLهای اسلش‌دار با آخرین خزش قدیمی‌اند. پس باید بازخزش تدریجی و سپس بازتحلیل ادامه یابد؛ تا آن زمان امتیاز سلامت اولیه است.

نسخهٔ آزمایشی backend/frontend با دیتابیس کپی‌شده و زمان‌بند خاموش فقط روی `127.0.0.1:3110` بالا آمد. آزمون HTTP ورود مدیر آزمایشی، منع دسترسی ناشناس، خروج و ابطال نشست، صفحهٔ گزارش و API گزارش Salimore را تأیید کرد؛ پاسخ API `coverage_status=partial` داشت. اطلاعات ورود آزمایشی در مخزن ثبت نشد و این آزمون هیچ کانتینر یا دیتابیس نسخهٔ زنده را تغییر نداد.
