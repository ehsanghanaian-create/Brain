# Obsidian vault

Path: `obsidian/SEO-Knowledge-Graph/` (override with `OBSIDIAN_VAULT_PATH`). Created by `scripts/setup.py --vault`; notes are generated by `scripts/build-graph.py`.

```
00-Sites/          SITE node (index of everything)
01-Pages/          WordPress pages + other crawled URLs (e.g. pagination)
02-Posts/          posts
03-Categories/     category terms (the archive URL's crawl data is merged into the category note)
04-Tags/           tags (none on this site)
05-Brands/  06-Models/  07-Services/  08-Locations/   extracted entities (with evidence)
09-Queries/        important GSC queries only (never all queries)
10-Schemas/        schema.org types (site-wide types link from the SITE note; page-specific ones from pages)
11-Problems/       one note per problem type listing affected pages
12-Opportunities/  one note per opportunity type
99-Reports/        Site Inventory, SEO Problems, SEO Opportunities
```

## Rules

* **A wikilink exists only for a real relationship** stored as a graph edge (LINKS_TO from crawled `<a>` tags, BELONGS_TO from WordPress taxonomy, ABOUT/OFFERS/TARGETS from entity mentions with title/H1/URL/taxonomy evidence, RANKS_FOR from GSC, HAS_SCHEMA, HAS_PROBLEM, HAS_OPPORTUNITY). Inbound links and "pages about this entity" are listed as plain text so the Obsidian graph is not double-counted.
* Suggested internal links (semantic) are plain text under *"Suggested internal links (semantic — not real links yet)"*.
* Frontmatter is real data only; GSC fields are `null` until synced.
* Wikilinks use full vault paths (`[[02-Posts/…|label]]`) so identical titles in different folders never collide.

## Plugins

* Graph View (core) — enabled via generated `.obsidian/core-plugins.json`; color groups per folder in `.obsidian/graph.json`.
* Dataview (community) — recommended, optional. Example: `TABLE gsc_impressions, internal_links_in FROM "02-Posts" SORT gsc_impressions DESC`.
* Local REST API (community, `obsidian-local-rest-api` 5.1.0, needs Obsidian ≥ 1.13.1) — **optional**; nothing in the pipeline depends on it. If enabled, `OBSIDIAN_API_URL/KEY` in `.env` allow read-only checks (preflight pings `/`).

## Verify (acceptance TEST 9)

Open the vault → Graph View → filter `path:01-Pages OR path:02-Posts OR path:03-Categories OR path:05-Brands OR path:06-Models OR path:07-Services OR path:08-Locations`; nodes should be colored by folder and connected by LINKS_TO/BELONGS_TO/ABOUT edges.
