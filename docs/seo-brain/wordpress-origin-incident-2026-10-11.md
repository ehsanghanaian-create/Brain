# اختلال اتصال وردپرس سالیمور — ۱۹ مهر ۱۴۰۵

## نتیجهٔ بررسی فقط‌خواندنی

مبدأ فعلی Nginx برای `api.salimore.com` برابر `146.19.212.122:443` است. درخواست مستقیم، بدون کش، از VPS به `/wp-json/` و `/wp-json/salimore/v1/health` روی این مبدأ HTTP 404 می‌گیرد. درخواست عمومی گاهی HTTP 200 با `X-Cache-Status: STALE` می‌دهد؛ این پاسخ، سلامت مبدأ فعلی را ثابت نمی‌کند.

مبدأ رسمی وردپرس `89.44.243.109:443` است. در ۱۱ اکتبر ۲۰۲۶، از سیستم محلی درخواست مستقیم به health و categories روی آن HTTP 200 گرفت (به‌ترتیب حدود ۸٫۳ و ۶٫۴ ثانیه). همان روز از VPS `185.221.237.158`، یک درخواست root HTTP 200 در ۸٫۳ ثانیه بود؛ چند دقیقه بعد هفت مسیر پیاپی با `Recv failure: Connection reset by peer` و HTTP 000 در حدود ۰٫۱۵ تا ۰٫۱۷ ثانیه شکست خوردند. آزمایش بعدی health پس از ۱۲ ثانیه بدون پاسخ timeout شد. مسیر خروجی VPS به این IP با source `185.221.237.158` تأیید شد. بنابراین مبدأ اصلی از VPS ناپایدار است.

آخرین اجرای **کامل** pipeline وردپرس SEO Brain `completed_with_errors` بود؛ خطای REST 404، با وجود موفقیت crawl و graph. اجرای `graph_only` همگام‌سازی وردپرس محسوب نمی‌شود. احراز هویت Application Password برای این سایت در backend فعلی تنظیم نشده و sync از REST عمومی فقط‌خواندنی استفاده می‌کند.

## اثر و اقدام لازم

- تا وقتی route مبدأ پایدار نشده، تغییر `salimore_wordpress_origin` از IP فعلی به IP رسمی بدون gate می‌تواند ورود، سفارش و پرداخت را ناپایدار کند. هیچ مسیر production در این بررسی تغییر نکرد.
- میزبان وردپرس/شبکه باید دسترسی پایدار از `185.221.237.158` به `89.44.243.109:443` را برقرار کند، یا IP تازه‌ای بدهد که همین WordPress و WooCommerce را سرو کند. همچنین باید روشن شود چرا edge پیشین `146.19.212.122` اکنون برای vhost `salimore.com` پاسخ 404 می‌دهد.
- پس از رفع مسیر، از خود VPS دست‌کم ۸ درخواست پیاپی برای REST root، health، types، taxonomies، categories، posts، محصولات و پاسخ اعتبارسنجی checkout بررسی شود؛ تازه بودن داده و یکسان بودن شناسهٔ محتوای دو مبدأ سنجیده شود. سپس با بکاپ Nginx، `nginx -t`، تغییر کنترل‌شده و بازگشت خودکار در صورت شکست gate، مسیر زنده اصلاح شود.
- در پایان، pipeline وردپرس SEO Brain با `stage=full` اجرا شود و وضعیت، تعداد صفحات/نوشته‌ها/رسانه‌ها و زمان تازه‌سازی گزارش شود. موفقیت crawl یا graph به‌تنهایی کافی نیست.

## متن آماده برای پشتیبانی میزبان

> سایت `salimore.com` روی WordPress/WooCommerce در مبدأ رسمی `89.44.243.109` است. سرور اپلیکیشن ما `185.221.237.158` از ۱۱ اکتبر ۲۰۲۶ برای HTTPS به `89.44.243.109:443` گاهی پاسخ 200 ولی مکرراً reset فوری TLS/HTTP یا timeout می‌گیرد؛ همان endpoint از اتصال مستقل 200 می‌دهد. edge قبلی `146.19.212.122` با Host/SNI برابر `salimore.com` برای `/wp-json/` و health اکنون 404 می‌دهد. لطفاً محدودیت/فایروال/route این source IP و وضعیت vhost هر دو IP را بررسی و IP مبدأ پایدار فعلی را اعلام کنید. این اختلال API محتوای سایت و مسیرهای پویا را تحت تأثیر قرار می‌دهد.

اطلاعات حساس، رمز و کلید در این سند ثبت نشده‌اند.
