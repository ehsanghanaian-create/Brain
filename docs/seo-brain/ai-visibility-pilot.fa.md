# پایلوت سنجش AEO و جست‌وجوی AI در SEO Brain

## هدف

این ماژول کمک می‌کند تیم برای یک سایت، تقاضای جست‌وجو، حضور در پاسخ‌های AI و نتیجهٔ قابل انتساب به کسب‌وکار را در یک مسیر بررسی کند. سه نوع داده جدا هستند و هیچ‌کدام جای دیگری را نمی‌گیرند:

| لایه | منبع | معنی عدد |
| --- | --- | --- |
| نمایش/استناد رسمی | ورود دستی از گزارش Generative AI در Search Console یا AI Performance در Bing Webmaster Tools | نمایش محتوای سایت در Google AI یا استناد Bing؛ بسته به گزارش |
| ارجاع و خرید | GA4 Data API، `sessionSource` دامنه‌های شناخته‌شده | نشست و خریدی که GA4 به یک ارجاع شناسایی‌شده نسبت داده است |
| پاسخ نمونه | مشاهدهٔ دستی یا OpenAI Responses API با ابزار `web_search` | پاسخ به یک پرسش ثابت در یک زمان؛ نه رتبهٔ واقعی، نه حجم کاربران و نه دادهٔ مصرف‌کنندگان ChatGPT |

Google AI Mode و AI Overviews معمولاً به صورت منبع ارجاع مستقل در GA4 قابل جداسازی نیستند. ترافیک direct و ارجاع‌های بدون نشانی نیز در شمارش AI وارد نمی‌شوند. وقتی پوشش همگام‌سازی کامل نباشد، عدد گزارش `—` است و صفر فرض نمی‌شود.

## راه‌اندازی

1. مهاجرت `0022_ai_visibility.sql` هنگام راه‌اندازی API اعمال می‌شود.
2. در داشبورد، «جست‌وجوی هوش مصنوعی» را باز کنید و سایت را انتخاب کنید.
3. همگام‌سازی GA4 را طبق روال موجود اجرا کنید. اجرای تازه یک گزارش جذب بر اساس منبع نشست و صفحهٔ فرود نیز می‌خواند. خطای این بخش در وضعیت همگام‌سازی دیده می‌شود و دادهٔ قبلی را پاک نمی‌کند.
4. از سرنخ‌های GSC یا پرسش‌های واقعی خریداران، پرسش‌های ثابت بسازید و صفحهٔ هدف را ثبت کنید.
5. پاسخ خام و لینک‌های منبع را دستی وارد کنید. در صورت وجود اتصال OpenAI، «نمونهٔ API» را فقط با اقدام صریح کاربر اجرا کنید. این فراخوانی هزینهٔ API دارد و سقف آن برای هر پرسش سه بار در روز است. پاسخ API تا بازبینی انسانی در نرخ ذکر برند محاسبه نمی‌شود.
6. گزارش رسمی را به صورت ردیف‌های `YYYY-MM-DD,count` برای مجموع سایت یا `YYYY-MM-DD,https://site/page,count` برای صفحه وارد کنید. خروجی کامل CSV کنسول باید ابتدا به این سه ستون نگاشت شود؛ همهٔ ستون‌های خام آن مستقیماً پذیرفته نمی‌شوند. برای یک روز و پلتفرم، ورود دوباره همان ردیف را جایگزین می‌کند.

## قواعد تفسیر و کنترل کیفیت

- مجموع رسمی سایت از ردیف‌های صفحه‌ای جداست؛ این دو با هم جمع نمی‌شوند.
- واحد پول درآمد از GA4 می‌آید. اگر واحد پول ردیف‌ها یکسان نباشد، مجموع درآمد نشان داده نمی‌شود.
- ذکر برند و نام رقبا در نمونه‌های API تنها با بازبینی انسان ثبت می‌شود. نرخ ذکر فقط از پاسخ‌های ارزیابی‌شده محاسبه می‌شود.
- لینک‌های استناد و متن پاسخ حفظ می‌شوند تا تیم بتواند یافته را بازبینی کند. پاسخ بدون جست‌وجوی وب موفق به عنوان نمونهٔ API ثبت نمی‌شود.
- پیشنهادهای GSC فقط تقاضای جست‌وجوی سنتی را نشان می‌دهند؛ خودشان شاهد حضور در AI نیستند.
- نتیجهٔ یک یا چند نمونهٔ API برای تصمیم محتوایی سرنخ است. تغییر محتوا باید با شواهد صفحه، نیاز کاربر و گزارش‌های رسمی بررسی شود.

این نسخه همگام‌سازی گزارش‌های رسمی گوگل و بینگ را خودکار نمی‌کند؛ ورود آن‌ها دستی و با نام منبع است. نمونهٔ OpenAI API نمایندهٔ پاسخ محصول مصرفی ChatGPT نیست. پیش از استفادهٔ مدیریتی از خرید و درآمد، پیکربندی رویداد خرید GA4 و واحد پول فروشگاه باید با سفارش‌های واقعی تطبیق داده شود.
